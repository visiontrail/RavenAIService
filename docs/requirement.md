# 日志暂存服务器详细需求文档

## 1. 项目概述

### 1.1 项目目标
开发一个基于 Python 的 HTTP 服务器，为系统日志文件提供上传、处理、下载和管理服务。该服务器特别针对协议栈日志提供专用的解压缩处理能力，支持将私有压缩格式转换为人类可读的文本格式。

### 1.2 核心价值
- **简化日志处理流程**：自动化处理复杂的协议栈日志解压
- **提升用户体验**：现代化 Web 界面，支持批量操作
- **智能存储管理**：自动清理策略，优化存储空间使用
- **便于分享协作**：支持日志详情页 URL 分享

## 2. 功能需求详述

### 2.1 日志上传服务

#### 2.1.1 上传接口规范
- **支持方法**：PUT 和 POST
- **文件格式**：tar.gz 压缩包
- **Content-Type**：multipart/form-data
- **文件大小限制**：1GB
- **并发上传**：支持多文件同时上传

#### 2.1.2 上传流程
1. 接收客户端上传的 tar.gz 日志包
2. 验证文件格式和完整性
3. 根据文件名判断日志类型
4. 存储到指定目录
5. 返回上传结果和后续处理信息

#### 2.1.3 错误处理
- 文件格式错误：返回 400 Bad Request
- 文件损坏：返回 422 Unprocessable Entity
- 存储空间不足：返回 507 Insufficient Storage
- 服务器错误：返回 500 Internal Server Error

### 2.2 日志列表管理

#### 2.2.1 列表展示内容
| 字段 | 类型 | 描述 | 备注 |
|------|------|------|------|
| 文件名 | String | 完整文件名 | 支持搜索和排序 |
| 文件大小 | String | 人类可读格式 | 如：1.2GB, 45.6MB |
| 创建时间 | DateTime | 文件上传时间 | 支持时间范围筛选 |
| 日志类型标签 | Tag | 视觉标识 | 协议栈日志/OAM与天线日志 |
| 处理状态 | Status | 当前状态 | 处理中/已完成/失败 |
| 进度条 | Progress | 处理进度 | 仅协议栈日志显示 |

#### 2.2.2 日志类型识别规则
- **协议栈日志**：文件名包含 "stack" 关键字
- **OAM与天线日志**：其他所有日志文件
- **标签样式**：使用不同颜色的 Badge 组件区分

#### 2.2.3 列表操作功能
- **单项操作**：
  - 删除：删除单个日志文件
  - 下载：直接下载文件
  - 复制链接：复制日志详情页链接
  - AI分析：预留功能（显示"敬请期待"）

- **批量操作**：
  - 多选框：支持全选和单选
  - 批量删除：一次性删除多个文件
  - 批量下载：打包下载多个文件

#### 2.2.4 用户交互反馈
- **复制链接成功**：短暂显示 Toast 提示"链接已复制"
- **删除确认**：弹出确认对话框
- **操作进度**：显示加载状态和进度条

### 2.3 协议栈日志处理服务

#### 2.3.1 处理触发条件
- 文件名包含 "stack" 关键字（大小写不敏感）
- 文件格式为 tar.gz
- 文件完整性验证通过

#### 2.3.2 处理工作流程

##### 步骤1：文件解压
```bash
# 解压上传的 tar.gz 文件到临时目录
tar -xzf /path/to/uploaded/stack_log.tar.gz -C /tmp/log_processing/
```

##### 步骤2：即时响应
```json
{
    "status": "accepted",
    "log_id": "unique_log_identifier",
    "download_url": "/download/unique_log_identifier",
    "estimated_completion": "2024-01-01T12:30:00Z"
}
```

##### 步骤3：异步处理状态更新
- 在日志列表中显示灰色状态的日志条目
- 所有操作按钮设为不可用状态
- 显示处理进度百分比

##### 步骤4：调用解压工具
```bash
tool_log_decompress [log_path] [thread_num]
```
- **log_path**：步骤1解压后的目录路径
- **thread_num**：处理线程数，默认14
- **工具功能**：将私有压缩格式转换为人类可读文本

##### 步骤5：重新打包
```bash
# 将处理后的文件重新打包
cd /path/to/processed/logs
tar -czf final_processed_log.tar.gz *
```

##### 步骤6：清理和完成
- 删除临时处理目录
- 更新日志状态为"已完成"
- 进度条跳转至100%
- 启用所有操作按钮

#### 2.3.3 进度估算算法
由于 `tool_log_decompress` 不提供进度回调，采用基于文件大小的估算：
- **假设处理速度**：100MB/s
- **进度计算公式**：progress = (elapsed_time * 100MB/s) / total_file_size * 100%
- **最大进度限制**：95%（为实际完成预留空间）

#### 2.3.4 错误处理机制
- **解压失败**：标记为失败状态，保留原文件
- **工具调用失败**：记录错误日志，提供重试选项
- **重打包失败**：回滚到原始文件

### 2.5 存储管理和自动清理

#### 2.5.1 清理策略配置
```python
CLEANUP_POLICIES = {
    "default_retention_days": 30,      # 默认保留30天
    "emergency_retention_days": 7,     # 紧急情况保留7天
    "disk_space_threshold_gb": 100,    # 磁盘空间阈值100GB
    "cleanup_check_interval": 3600,    # 检查间隔1小时
}
```

#### 2.5.2 清理执行逻辑
```python
def cleanup_logs():
    disk_space = get_disk_space_gb("/")
    
    if disk_space < CLEANUP_POLICIES["disk_space_threshold_gb"]:
        # 紧急清理：只保留7天
        cleanup_older_than(CLEANUP_POLICIES["emergency_retention_days"])
    else:
        # 常规清理：保留30天
        cleanup_older_than(CLEANUP_POLICIES["default_retention_days"])
```

#### 2.5.3 清理安全机制
- **软删除**：先移动到回收站目录
- **批量确认**：清理前生成清理报告
- **回滚能力**：24小时内可恢复误删文件
- **日志记录**：详细记录所有清理操作

### 3.3 容器化需求

#### 3.3.1 Docker镜像要求
```dockerfile
FROM python:3.11-slim

# 安装系统依赖
RUN apt-get update && apt-get install -y \
    tar gzip curl \
    && rm -rf /var/lib/apt/lists/*

# 复制应用代码
COPY . /app
WORKDIR /app

# 安装Python依赖
RUN pip install -r requirements.txt

# 复制解压工具
COPY tool_log_decompress /usr/local/bin/
RUN chmod +x /usr/local/bin/tool_log_decompress

EXPOSE 8080
CMD ["gunicorn", "--bind", "0.0.0.0:8080", "app:app"]
```

#### 3.3.2 部署脚本要求

**deploy.sh**
```bash
#!/bin/bash
# 构建镜像
docker build -t log-staging-service .

# 停止旧容器
docker stop log-staging-service 2>/dev/null || true
docker rm log-staging-service 2>/dev/null || true

# 启动新容器
docker run -d \
  --name log-staging-service \
  -p 8080:8080 \
  -v /data/logs:/app/logs \
  --restart unless-stopped \
  log-staging-service

echo "部署完成，服务运行在 http://localhost:8080"
```

**restart.sh**
```bash
#!/bin/bash
docker restart log-staging-service
echo "服务已重启"
```

**stop.sh**
```bash
#!/bin/bash
docker stop log-staging-service
echo "服务已停止"
```
