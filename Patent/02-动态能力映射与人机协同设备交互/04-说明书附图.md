**发明名称：一种基于动态能力映射与人机协同权限管控的AI智能体远程设备交互方法、系统、电子设备及存储介质**

## 图 1　AI智能体远程设备交互系统总体架构图

```mermaid
flowchart TB
    subgraph DEVICE["远程设备层"]
        D1["设备 A<br/>（协议 v2 · 在线）"]
        D2["设备 B<br/>（协议 v1 · 在线）"]
        D3["设备 C<br/>（离线 · 持久化恢复）"]
    end

    subgraph CONN["设备连接管理模块"]
        WS["WebSocket 长连接管理<br/>（注册／心跳／断线／能力更新）"]
        STORE["状态持久化<br/>（JSON 文件 · 服务重启恢复）"]
        PENDING["待处理映射表<br/>（request_id → Future）"]
    end

    subgraph MAPPING["动态工具映射模块"]
        EXTRACT["能力声明提取<br/>capabilities.mcp.servers[].tools[]"]
        SANITIZE["名称净化 · 模式归一<br/>· 风险别名归一"]
        PROXY["代理工具函数工厂<br/>（闭包生成 · 上限截断）"]
        META["工具元数据映射表<br/>ToolMeta{sdk_name,risk,...}"]
    end

    subgraph HITL["风险归类 + 权限代理模块"]
        CLASSIFY["三级风险归类器<br/>能力声明→规则匹配→默认 write"]
        BROKER["权限代理器<br/>PermissionBroker<br/>{request_id → Future}"]
        CLARIFY["澄清提问工具<br/>AskUserQuestion<br/>（共享 Broker）"]
    end

    subgraph HOOK["后置校验模块"]
        VALIDATE["信封解析 · 模式校验<br/>· 截断 · 脱敏"]
        REPLACE["updatedMCPToolOutput<br/>结果替换"]
    end

    subgraph ADAPT["协议适配模块"]
        V2["v2 JSON 信封<br/>action:mcp_call"]
        V1["v1 文本信封<br/>【DEVICE_TASK】"]
    end

    LLM["大语言模型推理引擎"]
    USER["用户端<br/>（SSE 事件流 + HTTP 裁决接口）"]

    D1 & D2 -->|"register / capabilities_update"| WS
    WS --> STORE
    WS --> EXTRACT --> SANITIZE --> PROXY --> META

    LLM -->|"工具调用"| CLASSIFY --> BROKER
    BROKER -->|"tool_permission_request"| USER
    USER -->|"allow / deny"| BROKER
    LLM -->|"AskUserQuestion"| CLARIFY --> BROKER

    BROKER -->|"allow"| PROXY
    PROXY --> ADAPT
    ADAPT --> V2 --> WS
    ADAPT --> V1 --> WS
    WS -->|"prompt"| D1 & D2
    D1 & D2 -->|"prompt_result"| PENDING
    PENDING --> PROXY

    PROXY -->|"工具输出"| VALIDATE --> REPLACE --> LLM
```

## 图 2　动态能力→工具映射流程图

```mermaid
flowchart TB
    START["会话开始<br/>获取目标设备 DeviceInfo"] --> EXT["提取 capabilities.mcp.servers[]"]
    EXT --> FLAT["展开为 (服务名, 工具名, 原始条目)<br/>按 (服务名, 工具名) 排序"]
    FLAT --> CAP{"工具总数 > 上限？"}
    CAP -->|是| TRUNC["截断：保留前 N 个<br/>发出 too_many_tools 通知"]
    CAP -->|否| LOOP
    TRUNC --> LOOP

    LOOP["遍历每个 (服务名, 工具名, 条目)"]
    LOOP --> SAN["名称净化<br/>[^A-Za-z0-9_] → _<br/>去首尾下划线"]
    SAN --> SCHEMA["参数模式归一化<br/>inputSchema / input_schema → 标准 dict<br/>缺失 → {type:object}"]
    SCHEMA --> RISK["风险等级归一化<br/>risk / x-risk → read|write|destructive<br/>别名映射（readonly→read 等）"]
    RISK --> TOOLMETA["创建 ToolMeta 记录<br/>{sdk_name, server, tool, description,<br/>input_schema, output_schema, risk}"]
    TOOLMETA --> CLOSURE["闭包工厂生成代理工具函数<br/>捕获: 分发器, 会话ID, 设备ID,<br/>协议版本, 事件发射器"]
    CLOSURE --> REG["注册到进程内工具服务器<br/>create_sdk_mcp_server(name='device')"]

    REG --> OUT["返回 (server, allowed_names, tool_meta_map)"]
```

## 图 3　三级风险归类与人机协同权限管控流程图

```mermaid
flowchart TB
    CALL["推理引擎发起工具调用<br/>触发 can_use_tool(tool_name, tool_input)"] --> LOOKUP["查找 ToolMeta"]
    LOOKUP --> P1{"ToolMeta.risk<br/>有效值？"}
    P1 -->|"read / write / destructive"| USE1["采用能力声明风险"]
    P1 -->|"无效 / 缺失"| P2{"风险规则列表<br/>有匹配？"}
    P2 -->|"命中规则"| USE2["采用规则声明风险"]
    P2 -->|"无匹配"| USE3["默认：write"]

    USE1 & USE2 & USE3 --> CHECK{"风险等级 == read？"}
    CHECK -->|是| ALLOW["直接返回 allow<br/>（短路放行）"]
    CHECK -->|否| GEN["生成 UUID request_id<br/>构造审批理由文本"]
    GEN --> MASK["mask_input 脱敏参数"]
    MASK --> EMIT["发出 tool_permission_request 事件<br/>（SSE → 用户端）"]
    EMIT --> OPEN["broker.open(request_id)<br/>创建 Future"]
    OPEN --> WAIT["await wait_for(future, timeout)"]
    WAIT --> TIMEOUT{"超时？"}
    TIMEOUT -->|是| DENY_T["broker.cancel<br/>发出 resolved(deny, timeout)<br/>返回 deny"]
    TIMEOUT -->|否| DECISION{"用户裁决"}
    DECISION -->|"allow"| ALLOW_U["发出 resolved(allow)<br/>返回 allow<br/>（若有 updated_args 附带）"]
    DECISION -->|"deny"| DENY_U["发出 resolved(deny, user_denied)<br/>返回 deny + message"]
```

## 图 4　单次设备工具调用全流程时序图

```mermaid
sequenceDiagram
    participant LLM as 大语言模型推理引擎
    participant CUT as can_use_tool 回调
    participant BRK as 权限代理器
    participant USR as 用户端
    participant PRX as 代理工具函数
    participant DSP as 分发器
    participant DLM as 设备连接管理模块
    participant DEV as 远程设备

    LLM->>CUT: 工具调用请求(tool_name, tool_input)
    CUT->>CUT: classify_risk → write
    CUT->>BRK: open(request_id)
    CUT->>USR: SSE: tool_permission_request
    USR->>BRK: POST resolve(request_id, allow)
    BRK-->>CUT: Future resolved → allow
    CUT-->>LLM: {behavior: allow}

    LLM->>PRX: 执行代理工具函数(args)
    PRX->>DSP: dispatch(server, tool, args)
    DSP->>DSP: 检测 protocol_version → 构造 JSON 信封
    DSP->>DLM: send_prompt(device_id, envelope)
    DLM->>DLM: 注册 pending Future
    DLM->>DEV: WebSocket: prompt 消息
    DEV->>DLM: WebSocket: prompt_result
    DLM->>DLM: 匹配 request_id → resolve Future
    DLM-->>DSP: 设备应答
    DSP-->>PRX: 结构化结果
    PRX-->>LLM: {content:[{type:text,text:json}]}

    Note over LLM: PostToolUse hook 拦截
    LLM->>LLM: 信封解析 → 模式校验 → 截断 → 脱敏
    LLM->>LLM: updatedMCPToolOutput 替换
    LLM->>LLM: 继续推理
```

## 图 5　后置校验钩子处理流程图

```mermaid
flowchart TB
    INPUT["PostToolUse hook 触发<br/>matcher: mcp__device__*"] --> EXTRACT["信封解析<br/>content[0].text → JSON"]
    EXTRACT --> PARSE{"解析成功？"}
    PARSE -->|否| SM1["构造 schema_mismatch<br/>占位 envelope"]
    PARSE -->|是| SIZE1{"总长度 > max_bytes？"}
    SM1 --> SIZE1
    SIZE1 -->|是| TOO_LARGE["替换为<br/>{error_kind: result_too_large}"]
    SIZE1 -->|否| ERR{"设备返回了<br/>error 状态？"}
    ERR -->|是| NORM_ERR["归一化 error_kind<br/>（非已知类型 → internal_error）<br/>脱敏 error_message<br/>截断 evidence"]
    ERR -->|否| SCHEMA{"outputSchema<br/>校验通过？"}
    SCHEMA -->|否| SM2["替换为 schema_mismatch<br/>附截断原始摘要"]
    SCHEMA -->|是| MASK_R["mask_input 脱敏 result<br/>逐条截断 evidence<br/>（UTF-8 安全回退）"]
    MASK_R --> SIZE2{"处理后总长度<br/>> max_bytes？"}
    SIZE2 -->|是| TOO_LARGE
    SIZE2 -->|否| OK["正常通过"]

    TOO_LARGE & NORM_ERR & SM2 & OK --> EMIT["发出 result_validation 事件<br/>（status, reason）"]
    EMIT --> REPLACE["序列化为 JSON<br/>封装为 updatedMCPToolOutput<br/>替换原始工具输出"]
```

## 图 6　协议版本自适应分发流程图

```mermaid
flowchart TB
    CALL["分发器接收工具调用<br/>(server, tool, args)"] --> READ["读取 device.capabilities.protocol_version<br/>非整数容错为 0"]
    READ --> CHECK{"protocol_version ≥ 2？"}
    CHECK -->|是| V2["构造 JSON 信封<br/>{protocol_version:2,<br/>action:'mcp_call',<br/>server, tool, args,<br/>request_id, ts}"]
    CHECK -->|否| LEGACY["构造文本信封<br/>【DEVICE_TASK】…【/DEVICE_TASK】"]
    LEGACY --> NOTICE{"同一会话首次<br/>使用文本信封？"}
    NOTICE -->|是| EMIT["发出 system_notice<br/>legacy_envelope 降级通知<br/>设置 _legacy_sent 标记"]
    NOTICE -->|否| SKIP["跳过通知"]
    EMIT --> WRAP
    SKIP --> WRAP
    V2 --> WRAP["封装为 PromptEnvelope<br/>{request_id, session_id,<br/>prompt, target_device_id,<br/>metadata{source, protocol_version,<br/>server, tool}}"]
    WRAP --> SEND["device_link_manager.send_prompt<br/>→ WebSocket 发送"]
    SEND --> WAIT["await Future（设备超时控制）"]
    WAIT --> PARSE["_parse_device_reply<br/>统一解析设备回包"]
```

## 图 7　主动澄清提问流程图

```mermaid
flowchart TB
    TRIGGER["推理引擎调用 AskUserQuestion<br/>{questions: [...]}"] --> NORM["规范化问题列表<br/>丢弃无效条目"]
    NORM --> VALID{"有效问题 > 0？"}
    VALID -->|否| SKIP["返回'未提供有效问题'<br/>提示模型继续"]
    VALID -->|是| LIMIT{"已提问次数<br/>≥ max_rounds？"}
    LIMIT -->|是| MAXED["返回'已达上限'<br/>提示模型自行决断"]
    LIMIT -->|否| COUNT["计数 +1"]
    COUNT --> OPEN["broker.open_clarification(request_id)<br/>创建 Future（risk='clarify'）"]
    OPEN --> EMIT["发出 clarification_request 事件<br/>{questions, request_id,<br/>run_id, session_id}"]
    EMIT --> WAIT["await wait_for(future, timeout)"]
    WAIT --> RESULT{"等待结果"}
    RESULT -->|"用户作答"| FORMAT["_format_answers<br/>格式化为结构化文本"]
    RESULT -->|"超时"| TIMEOUT{"on_timeout 策略"}
    TIMEOUT -->|"continue"| CONT["返回'请基于已知信息继续'"]
    TIMEOUT -->|"cancel"| CANCEL["调用 cancel_run 回调<br/>返回'本轮已取消'"]
    FORMAT --> RETURN["回喂模型继续推理"]

    subgraph Q_SCHEMA["单个问题的结构"]
        QH["header（≤12 字标签）"]
        QT["question（完整问题文本）"]
        QM["multiSelect（可选·布尔）"]
        QO["options[2~4]（每个含 label + description）"]
    end
```

## 图 8　设备连接生命周期与状态持久化流程图

```mermaid
flowchart TB
    subgraph LIFECYCLE["设备连接生命周期"]
        REG["register 消息到达<br/>（携带 device_id, capabilities, ...）"]
        REG --> OLD{"同 ID 旧连接存在？"}
        OLD -->|是| CLOSE_OLD["关闭旧 WebSocket"]
        OLD -->|否| CREATE
        CLOSE_OLD --> CREATE["创建/更新 DeviceState<br/>标记 online"]
        CREATE --> PERSIST1["持久化设备列表"]

        HB["心跳（ping/pong）"]
        HB --> UPDATE["更新 last_seen + online"]
        UPDATE --> PERSIST2["持久化设备列表"]

        DISC["WebSocket 断开"]
        DISC --> OFFLINE["标记 offline<br/>清空 WebSocket 引用"]
        OFFLINE --> FAIL["遍历待处理映射表<br/>以断连异常完成所有<br/>该设备的 pending Future"]
        FAIL --> PERSIST3["持久化设备列表"]

        CAP_UP["capabilities_update 消息"]
        CAP_UP --> UPD_CAP["更新 capabilities dict<br/>更新 last_seen"]
        UPD_CAP --> PERSIST4["持久化设备列表"]
    end

    subgraph RESTART["服务重启恢复"]
        BOOT["服务启动"]
        BOOT --> LOAD["读取 device_links.json"]
        LOAD --> RESTORE["逐条解析 DeviceInfo<br/>标记 offline（WebSocket=null）<br/>加入设备映射表"]
        RESTORE --> READY["恢复完成<br/>等待设备重新 register"]
    end

    subgraph PROMPT_MATCH["请求-响应匹配"]
        SEND["send_prompt(device_id, envelope)"]
        SEND --> REG_F["创建 Future<br/>注册到 pending 映射表"]
        REG_F --> WS_SEND["WebSocket 发送 prompt 帧"]
        WS_SEND --> WAIT_F["await wait_for(future, timeout)"]

        RECV["handle_prompt_result"]
        RECV --> MATCH["按 request_id 查找 pending"]
        MATCH --> CHECK_D{"device_id 一致？"}
        CHECK_D -->|否| WARN["日志警告 mismatch"]
        CHECK_D -->|是| RESOLVE["future.set_result(payload)<br/>从 pending 移除"]
    end
```
