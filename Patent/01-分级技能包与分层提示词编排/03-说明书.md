# 说明书

**发明名称：一种基于分级技能包与分层提示词编排的多智能体服务方法、系统、电子设备及存储介质**

---

## 一、技术领域

本发明涉及人工智能与计算机软件技术领域，尤其涉及一种基于分级技能包与分层提示词编排的多智能体（Multi-Agent）服务方法、系统、电子设备及计算机可读存储介质，可应用于智能测试平台、智能运维平台、代码分析平台等以项目为组织单元、由多个大语言模型智能体协同工作的服务端系统。

## 二、背景技术

随着大语言模型（Large Language Model，LLM）技术的发展，基于大语言模型构建的智能体（Agent）被广泛应用于日志分析、代码问答、缺陷修复、设备联动等企业级场景。在实际部署中，一个服务端系统往往同时承载多个业务项目与多个专业智能体：不同项目具有不同的代码仓库、日志格式、术语体系与排查经验；不同智能体具有不同的任务定位、工具集合与输出契约。

现有技术中，为智能体注入领域知识与行为约束的主流方案存在如下缺陷：

（1）**单体提示词方案**：将系统提示词写成单一的大段文本，把所有项目知识、排查经验、格式要求全部塞入其中。该方案在多项目场景下无法隔离不同项目的知识，提示词彼此污染；且任何一个项目的知识变更都需要整体修改提示词，维护成本高、变更风险大。

（2）**全量知识注入方案**：将全部领域知识文档在每次推理前拼接进上下文。该方案导致上下文窗口（Context Window）被大量与当前问题无关的内容占用，推理成本（token 消耗）显著上升，且过长的无关内容会稀释模型注意力、降低回答质量。

（3）**服务端预筛方案**：由服务端通过关键词匹配或向量检索预先筛选与当前请求"可能相关"的知识片段再注入。该方案的相关性判定发生在推理之前，无法覆盖模型在推理中途才暴露出的知识需求；预筛错误会直接导致关键知识缺失，且需要额外维护检索索引。

（4）**扁平知识库方案**：知识包（技能包）不区分归属层级，所有智能体共享同一知识池。该方案无法表达"某知识仅对某项目生效""项目知识应覆盖通用知识"等治理需求，也无法在项目维度上做权限隔离。

（5）**静态提示词配置方案**：提示词硬编码于程序或需重启服务才能生效，多管理员并发编辑时存在相互覆盖的风险；且项目初始化时提示词为空，管理员需要针对每个新项目从零撰写工作流指令，一致性差。

综上，现有技术缺乏一种能够同时解决**知识分级治理、上下文按需占用、提示词分层组装、项目差异化初始化与配置热更新**的完整技术方案。

## 三、发明内容

### （一）要解决的技术问题

本发明所要解决的技术问题包括：

1. 多项目多智能体场景下，领域知识（技能包）缺乏层级化的归属、隔离与覆盖机制；
2. 领域知识全量注入导致上下文窗口占用过大、推理成本高、注意力被稀释；
3. 系统提示词单体化导致项目专属约束与通用约束纠缠、维护困难、变更风险大；
4. 新建项目的提示词冷启动问题，以及项目在"关联代码仓库/未关联代码仓库"两种形态间切换时工作流指令的适配问题；
5. 提示词配置并发编辑冲突与变更生效延迟问题；
6. 上传技能包引入的解压炸弹、目录穿越等安全风险。

### （二）技术方案

为解决上述技术问题，本发明提供一种基于分级技能包与分层提示词编排的多智能体服务方法，其总体构思为：**在知识维度建立"智能体级/项目级"两级技能包体系并在运行时合并物化，在指令维度建立"基础层/项目层/运行时层"分层提示词体系并按确定性顺序拼接，同时将技能相关性判定从服务端预筛移至大语言模型推理过程中的按需加载**。

方法主要步骤如下：

**步骤 S1，两级技能注册表维护。** 服务端维护智能体级技能注册表（按智能体标识 `agent_key` 隔离）与项目级技能注册表（按项目标识 `project_code` 隔离）。每一技能以技能包目录形式存储，目录内至少包含携带结构化元描述头（frontmatter）的技能描述文件（`SKILL.md`），元描述头至少含 `name`（技能名称）与 `description`（技能描述）字段。技能包以压缩包上传，入库前执行安全校验：压缩包字节数、条目数、累计解压字节数三重阈值校验；逐条目拒绝绝对路径与上级目录引用并校验解压目标归属，阻断目录穿越；解析元描述头并按预设正则校验技能名称合法性。

**步骤 S2，运行工作区创建与技能合并物化。** 响应针对目标智能体与目标项目的运行请求，创建与本次运行绑定的隔离运行工作区。遍历两级注册表中处于启用状态的技能，按"智能体级在先、项目级在后，同名项目级覆盖"的合并顺序物化至工作区约定技能目录（如 `.claude/skills/<name>/`）。物化优先采用符号链接以避免复制开销，符号链接不可用时回退为递归复制；物化前清理同名旧目录。物化完成后向推理引擎运行配置注入项目级设置源，使其按约定自动发现技能。

**步骤 S3，分层系统提示词拼接。** 按确定性顺序构建系统提示词：

1. **智能体基础层**：按智能体标识与语言标识（locale）从提示词配置文件中选取，支持"语言标识→正文"多语言映射与默认语言回退；
2. **运行时上下文段**：注入本次运行工作区的真实路径信息（工作目录、任务文件、源码目录等）；
3. **项目级附加段**：合并"智能体专属层→项目共享层"两层项目提示词，冠以含项目名称的标题与优先级声明（项目专属约束在不违背安全与输出格式底线的前提下优先于通用指令），两层均空时该段为空串；
4. **技能可用性菜单段**：仅注入各已物化技能的"名称＋描述"菜单、按需加载使用规则（使用前必须经技能加载工具读取全文、推理中途可随时补充加载、无关技能不加载）与事实校验规则（技能为辅助参考，代码事实以工作区真实源码/日志为准）；
5. **回复语言指令段**：置于末位，将回复语言与输入语料语言解耦。

**步骤 S4，推理执行与按需加载。** 将拼接后的系统提示词与用户提示词提交大语言模型推理引擎。模型在推理过程中依据菜单段自行判定技能相关性，仅对相关技能调用技能加载工具读取全文，实现上下文的按需占用。

进一步地，方法还包括：

**默认提示词幂等播种机制**：项目创建或仓库关联状态变化时，依据项目是否关联代码仓库，分别选取"代码工作流模板"或"无仓库工作流模板"播种至受播种智能体的项目专属层。播种时比对现有内容：等于当前变体则跳过；等于另一变体的未改动默认值则替换（适配仓库状态切换）；与两种变体均不同则判定为管理员已自定义，保留不覆盖。

**提示词热更新机制**：更新请求携带期望校验和，与磁盘当前内容校验和不一致且未指定强制标志时拒绝（乐观并发控制）；通过临时文件写入加原子替换持久化；随后使各智能体提示词内存缓存失效，实现免重启即时生效。

**拼接预览机制**：返回"基础层＋项目级附加段"的组合预览及各层存在性、字节数、更新时间元数据，刻意排除运行时动态段，供管理员在配置阶段审查最终指令形态。

**运行时适配机制**：项目未关联仓库时注入"禁止克隆仓库"约束段；模型提供方不支持外部工具协议（MCP）时过滤相应工具并注入替代路径约束段。

**输出契约保障机制**：菜单段声明最终输出仍须遵守结构化输出契约；技能要求输出裸文本时，将裸文本包装入结构化 JSON 的对应字段并记录包装标记。

本发明还相应提供实现上述方法的多智能体服务系统（含技能管理模块、提示词配置模块、工作区编排模块、提示词拼接模块、推理执行模块）、电子设备及计算机可读存储介质。

### （三）有益效果

与现有技术相比，本发明具有如下有益效果：

1. **上下文占用显著降低**：技能全文不进入初始上下文，仅注入名称与描述菜单（每技能通常数十字节），由模型推理中按需加载，在技能库规模增长时初始上下文占用近似常数级增长，降低 token 成本并避免注意力稀释；
2. **知识分级治理**：智能体级与项目级技能物理隔离、同名项目级覆盖，天然表达"项目知识覆盖通用知识"的治理语义，支持项目维度的权限与生命周期管理；
3. **提示词职责分离**：基础层承载智能体通用能力，项目层承载项目专属约束，运行时层承载单次运行的动态事实，任一层的变更不影响其他层，降低维护成本与变更风险；
4. **冷启动与形态切换自动化**：新项目自动获得与其"是否关联仓库"形态匹配的工作流指令，且形态切换时幂等替换、人工定制不被覆盖；
5. **配置变更安全即时**：校验和乐观并发控制避免多管理员相互覆盖，原子写入避免半成品文件，缓存失效使变更免重启生效；
6. **技能供应链安全**：三重阈值与路径归属校验阻断解压炸弹与目录穿越攻击；
7. **回答可信度提升**：事实校验规则强制模型以真实源码/日志核验技能中的代码事实，防止过时知识污染答案；
8. **物化零拷贝**：符号链接优先的物化方式使技能包在多次运行间零拷贝复用，降低磁盘与 I/O 开销。

**合并物化算法**（对应权利要求 1、5）伪代码如下：

```
materialize_enabled_skills(agent_key, target_dir, project_code):
    skills_dir = target_dir / ".claude/skills"; 确保存在
    materialized = []
    # 第一遍：智能体级技能
    for entry in enabled(agent_registry[agent_key]):
        link_skill(entry.name, agent_store_dir(entry))
    # 第二遍：项目级技能——同名覆盖
    if project_code:
        for entry in enabled(project_registry[project_code]):
            link_skill(entry.name, project_store_dir(entry))
    return materialized

link_skill(name, src):
    dst = skills_dir / name
    清理 dst 既有文件/目录/符号链接
    try:    os.symlink(src.resolve(), dst)      # 零拷贝优先
    except: shutil.copytree(src, dst)           # 环境不支持时回退复制
    materialized.append(name)  # 去重追加
```

第二遍对同名技能重新执行 `link_skill` 即完成"项目级覆盖智能体级"，无需额外冲突消解逻辑；`enabled_skill_overviews` 接口按相同顺序合并名称与描述，保证菜单段所宣告的技能集合与实际物化结果严格一致。

其中项目级附加段的生成逻辑（对应权利要求 2）为：

```
build_project_prompt_addendum(project_code, agent_key, project_name):
    sections = []
    agent_text  = 读取(project_code, agent_key)   # 智能体专属层
    if agent_text: sections.append(agent_text)
    shared_text = 读取(project_code, None)        # 项目共享层
    if shared_text and shared_text != agent_text: sections.append(shared_text)
    if not sections: return ""                    # 双层皆空 → 不拼接
    body = "\n\n---\n\n".join(sections)
    return "## 项目级附加系统指令（{项目名}）\n"
           "……在不违背安全约束与最终输出格式要求的前提下，"
           "这些项目特定的约束优先于通用指令……\n\n" + body
```

项目级提示词的磁盘布局按项目标识隔离、按智能体标识分层：

```
data/project_prompts/
└── <project_code>/
    ├── system_prompt.md                # 项目共享层（对所有智能体生效）
    ├── project_expert/system_prompt.md # 智能体专属层（仅项目专家）
    ├── log_analysis/system_prompt.md   # 智能体专属层（仅日志分析）
    └── package_search/system_prompt.md # 智能体专属层（仅包检索）
```

单层提示词设有字符上限（本实施例为 20000 字符）以防异常大文件拖垮上下文；`agent_key` 取值经白名单校验，白名单同时充当路径白名单，从根源上阻断 `../` 目录穿越；读取路径不设缓存，管理员编辑后对后续运行立即生效。

**技能可用性菜单段**（对应权利要求 1、7、12）的关键设计在于"菜单换全文"：初始上下文仅含每个技能一行的 `- \`name\`：description` 菜单及三类规则——

1. **按需加载规则**：使用任何技能前必须先经技能加载工具读取全文；推理中途可随时补充加载；无关技能不得加载以免浪费上下文；
2. **事实校验规则**：技能是辅助参考而非代码事实权威；技能中涉及文件路径、符号名、字段、枚举、行号、接口签名、调用关系的描述必须先到工作区真实源码/日志中检索核对再作答；冲突时以真实代码为准，并可在回答中声明"技能描述与当前代码不一致，已以代码为准"；方法论、检查清单类内容仍应遵循；
3. **输出契约重申**：最终输出必须遵守既定结构化 JSON 契约；技能要求输出特定裸文本时，将其原样放入 JSON 的 `answer`/`summary` 字段而非输出裸文本。

同时菜单段显式给出各技能的物化路径（`.claude/skills/<name>/`），指示相对路径资源按物化目录解析，避免脚本/模板引用错位。

### 实施例四：智能体运行全流程

如图 4 的时序所示，一次项目专家智能体运行的完整流程为：

1. 服务接收运行请求（含项目标识、语言标识、用户问题），创建隔离运行工作区并写入任务文件 `task.json`；
2. 按 agent_key × locale 读取基础层提示词，拼接运行时上下文段；
3. 探测模型提供方能力：支持 MCP 则挂载项目仓库查询工具服务，否则过滤 `mcp__` 前缀工具并注入运行时约束段；
4. 读取任务中的 `repo_info`：`repo_url` 为空时注入无仓库约束段；
5. 调用 `build_project_prompt_addendum(project_code, agent_key)` 生成项目级附加段并拼接；
6. 调用 `materialize_enabled_skills(agent_key, workspace, project_code)` 完成两级技能合并物化，再以 `enabled_skill_overviews` 取回与物化结果严格一致的名称/描述集合，生成技能可用性菜单段，同时拼接进系统提示词与用户提示词；
7. 存在已物化技能时，向推理引擎运行配置注入 `setting_sources=["project"]`，使其按约定从工作区发现技能；
8. 末位拼接回复语言指令段，构建运行选项（工作目录、允许工具集、权限模式、MCP 服务），提交推理引擎流式执行；
9. 推理过程中模型按需经 Skill 工具加载技能全文、经 Read/Grep/Bash 等工具访问工作区真实代码与日志，事件流（含"已加载技能"系统通知）经追踪回调以 SSE 推送前端；
10. 运行结束输出结构化 JSON 结果；若技能指定了裸文本输出，则按输出契约保障机制包装为 `{status, answer, summary, related_keywords, parse_warning:"plain_text_skill_answer_wrapped", …}` 形态。

### 实施例六：提示词配置的热更新与并发控制

如图 7 所示，基础层提示词集中存储于单一 YAML 配置文件，按"功能键 → 智能体变体 → 字段 → 语言"四级组织，例如 `claude_agent_project_expert.generic.system_prompt.zh`。管理端提供两种更新通道（对应权利要求 9）：

<table border="1" cellspacing="0" cellpadding="6">

    <tr><th>通道</th><th>粒度</th><th>校验</th></tr>
