## ADDED Requirements

### Requirement: AgentTraceStream 组件

系统 SHALL 提供单一前端组件 `AgentTraceStream.vue`（`frontend/src/components/`），输入为响应式 `events: AgentTraceEvent[]` 与 `running: boolean`，输出工具调用与思考过程的可折叠步骤卡片视图。组件 MUST 同时被 `AIChat.vue`（AI 对话页）与 `LogDetail.vue`（日志详情页）复用，且不依赖具体的 SSE 来源。

组件 MUST 按事件 `seq` 升序处理，重复 `seq` MUST 被丢弃，事件源乱序到达时 MUST 仍渲染出正确顺序。

#### Scenario: 同一组件双入口复用

- **WHEN** 同一份 `AgentTraceEvent[]` fixture 分别注入 AIChat 和 LogDetail 页面挂载的 `AgentTraceStream`
- **THEN** 两侧渲染输出 MUST 完全一致

#### Scenario: 乱序与去重

- **WHEN** 事件以 [seq=1, seq=3, seq=2, seq=3] 顺序到达
- **THEN** 组件 MUST 渲染 seq=1, 2, 3 三个事件的合并结果，重复 seq=3 被丢弃

### Requirement: 步骤卡片四态与流式展示

每个 step 卡片 SHALL 由 `step_start` → `step_delta*` → `step_end` 推进，并具有 `running` / `ok` / `error` / `cancelled` 四种状态。

- `running` 状态 MUST 默认展开，工具输入 MUST 立即显示，输出区 MUST 按 `step_delta.output_chunk` 流式 append，光标 / 加载指示器 MUST 可见；
- `ok` / `error` / `cancelled` 三种终态 MUST 默认折叠为单行，单行 MUST 包含工具名、输入摘要、duration、状态图标；
- 用户点击单行 MUST 展开恢复完整输入 + 输出 + 状态详情，展开态 MUST 持久（直到组件销毁）。

思考块（`thinking_*`）卡片 MUST 与 tool 卡片**视觉上区分**（不同图标 / 不同色调），其余交互（运行中展开、终态折叠、点击恢复）规则相同。

#### Scenario: 运行中工具卡片流式输出

- **WHEN** 后端推送 `step_start{tool_name: "Bash", tool_input: {command: "git clone ..."}}` 后陆续推送 4 条 `step_delta{output_chunk: "..."}`
- **THEN** 卡片 MUST 立即出现并展开，工具名 / 输入立即可见，输出区随 4 条 delta 增量 append，最后一字符前 MUST 显示运行光标

#### Scenario: 工具完成自动折叠

- **WHEN** 卡片收到 `step_end{status: "ok", duration_seconds: 1.2}`
- **THEN** 卡片 MUST 在 ≤ 200ms 内折叠为一行 `Bash · git clone ... · 1.2s · ok`，光标消失，状态图标显示成功

#### Scenario: 用户手动展开已折叠卡片

- **WHEN** 已折叠的 `ok` 卡片被用户点击
- **THEN** 卡片 MUST 重新展开显示完整 `tool_input` + 完整 `output_excerpt`，展开态 MUST 持续到组件卸载

#### Scenario: 思考卡片与工具卡片视觉区分

- **WHEN** 同一 trace 中既有 `step_*`（tool）也有 `thinking_*` 卡片
- **THEN** 思考卡片 MUST 使用不同图标和文案前缀（如 `Thinking`）与工具卡片视觉区分

### Requirement: 最终汇总一行折叠

当组件收到 `run_complete` / `cancelled` / `error` 之一作为终态时，所有内部 step / thinking 卡片 SHALL 被一个外层"汇总条"覆盖。汇总条 MUST 显示：

- 正常完成：`Thought for {trace_summary.thought_duration_seconds.toFixed(1)}s · {trace_summary.tool_call_count} tool calls`
- 取消：`Cancelled after {duration}s · {tool_call_count} tool calls`
- 错误：`Failed after {duration}s · {tool_call_count} tool calls`

汇总条下方 MUST 显示固定副标题 `Generated by AI and can make mistakes`。

汇总条 MUST 默认折叠（仅一行 + 副标题）。点击汇总条 MUST 展开恢复显示所有 step / thinking 卡片，每张卡片维持自己的折叠状态。

#### Scenario: 正常完成的最终汇总

- **WHEN** 组件收到 `run_complete{trace_summary: {thought_duration_seconds: 42.3, tool_call_count: 22}}`
- **THEN** 卡片列表 MUST 立即被替换为一行 `Thought for 42.3s · 22 tool calls`，下方一行 `Generated by AI and can make mistakes`

#### Scenario: 展开最终汇总

- **WHEN** 用户点击折叠后的汇总条
- **THEN** 组件 MUST 展开还原所有原始卡片，卡片各自的折叠态保留

#### Scenario: 取消态文案

- **WHEN** 组件收到 `cancelled{trace_summary: {tool_call_count: 4, thought_duration_seconds: 8.1}}`
- **THEN** 汇总条文案 MUST 为 `Cancelled after 8.1s · 4 tool calls`，副标题不变

### Requirement: AIChat.vue 接入

`AIChat.vue` SHALL 在 SSE `processChunk` 中识别 `event === "agent_trace"` 的帧并把 payload append 到当前正在生成的 assistant 消息的 `traceEvents` 数组中；`AgentTraceStream` 组件 MUST 在该消息气泡内渲染。

当 SSE 收到 `done` 事件时，组件 MUST 接收到 `running = false`，触发最终一行折叠。

#### Scenario: agent_trace 路由进当前消息

- **WHEN** 用户发起一次带文件的日志分析，SSE 流先后下发 `session`、`log_analysis_status`、若干 `agent_trace`、`done`
- **THEN** 所有 `agent_trace` payload MUST 被 append 到该轮对话气泡的 `traceEvents` 数组，并实时渲染

### Requirement: LogDetail.vue 接入

`LogDetail.vue` SHALL 在 AI 分析模块挂载 `AgentTraceStream` 组件，并在分析任务为运行态时打开 `/api/v1/logs/{log_id}/ai-analysis/trace/stream` SSE 连接。组件卸载或任务终态时 MUST 关闭 SSE 连接。

页面刷新或首次进入已完成的日志详情时，组件 MUST 从 `log.ai_analysis_result.trace_events` 一次性加载历史事件并渲染为终态（直接显示最终一行折叠汇总，且可展开还原）。

#### Scenario: 运行中页面进入

- **WHEN** 日志详情页打开时分析任务处于运行态
- **THEN** 组件 MUST 立即打开 trace SSE 连接，按到达顺序渲染卡片，直到收到 `run_complete`

#### Scenario: 刷新后回放

- **WHEN** 用户在任务完成后刷新页面或重新进入该日志详情
- **THEN** 组件 MUST 从 `ai_analysis_result.trace_events` 加载历史事件，渲染为已折叠的最终汇总条，用户点击可展开所有卡片

#### Scenario: 卸载关闭连接

- **WHEN** 用户在分析运行中离开日志详情页
- **THEN** SSE 连接 MUST 在 1 秒内被前端主动关闭，且 ≤ 1 条已 in-flight 事件被允许丢弃

### Requirement: 工具名展示与未知工具回退

组件 SHALL 维护一份工具显示名映射表（如 `Bash → 终端`、`Read → 读文件`、`mcp__project_repo__lookup_project_repo → 项目仓库查询`）。未匹配的工具名 MUST 原样展示，不报错。

#### Scenario: 已映射工具名

- **WHEN** 步骤 `tool_name == "Bash"`
- **THEN** 卡片显示名 MUST 为映射表中的友好名（如 `终端`），原始 tool_name 可作为 hover tooltip

#### Scenario: 未映射工具名

- **WHEN** 后端推送了一个组件不认识的 `tool_name`（如 `WebFetch`）
- **THEN** 卡片显示名 MUST 直接使用原始字符串 `WebFetch`，组件 MUST NOT 抛错或丢弃事件

### Requirement: 取消按钮交互（条件）

当上层页面（`AIChat.vue` 或 `LogDetail.vue`）能提供取消 API 时，`AgentTraceStream` 组件 SHALL 在运行态下显示取消按钮并通过 emit `cancel` 事件让上层调用对应 API。取消请求发出后，组件 MUST 立即把按钮状态切换为 `cancelling`（disabled + 文案变更）直到收到终态事件。

若上层未传 `onCancel` prop，取消按钮 MUST 不渲染。

#### Scenario: 用户取消

- **WHEN** 用户在 chat 入口分析进行中点击取消按钮
- **THEN** 组件 MUST emit `cancel`，按钮切换为 `cancelling` 状态，直到收到 `cancelled` 终态事件后整体折叠为 `Cancelled after Xs · N tool calls`

#### Scenario: 入口未提供取消能力

- **WHEN** 日志详情入口因后端尚未提供 cancel API，未传 `onCancel`
- **THEN** 组件 MUST NOT 渲染取消按钮，其他渲染行为不变
