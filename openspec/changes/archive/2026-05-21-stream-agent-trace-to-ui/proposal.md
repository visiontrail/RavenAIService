## Why

日志分析已经迁移到 Claude Agent SDK 的 agent loop（参见已落地的 `rebuild-log-analysis-with-claude-agent-sdk` 变更），SDK 内部本身就是按消息流（assistant text、tool_use、tool_result、thinking、system 等）推送的，但目前前端**完全感知不到这条流**：

- 在 **AI 对话页** (`AIChat.vue`)，`/ai-chat/log-analysis/stream` SSE 通道只下发 `log_analysis_status`（粗粒度占位文案）、`log_analysis_context`、`done`、`error`，工具调用与中间思考完全没透传；
- 在 **日志详情页** (`LogDetail.vue`)，AI 分析走 Celery 任务，前端只能轮询 `ai_analysis_status / progress`，必须等任务跑完才能看到一次性的结论。`tool_trace` 虽然作为字段最终一起返回，但用户在分析过程中只能看到一个旋转的 loading；
- Agent 内部 `_handle_stream_message`（`app/agents/log_analysis/agent.py`）已经在按消息粒度处理，但当前只 `_log_workflow(...)` 写日志、`tool_trace.append(...)` 写最终结果，**没有把每一条消息作为事件向外推**。

这导致一次分析动辄运行 30–90s，用户体验上完全是个黑盒——既看不到 AI 在想什么，也没法判断是不是卡住了，更没办法在中途取消（取消机制虽存在，但用户没有任何信号去判断要不要取消）。

我们希望前端获得**类似 Claude Code Coding Agent 的实时步骤流**：

- 每一个工具调用（`Bash`/`Read`/`Grep`/`Glob`/`Skill`/`mcp__project_repo__lookup_project_repo`）以一张"步骤卡片"形式实时出现，展开显示输入、输出（流式 append）、状态（running / ok / error）；
- 每一段 thinking / assistant 文本以单独的"思考卡片"形式实时出现，文本流式 append；
- 当前步骤完成后自动折叠（仅显示一行标题，例如 `Bash · git clone … · 1.2s · ok`、`Thought · 312 chars`）；
- 任务完成后所有步骤再次合并折叠为一行汇总（`Thought for 42.3s · 22 tool calls · Generated by AI and can make mistakes`），点击可重新展开整条 trace；
- 取消、超时、错误以同一套事件协议体现。

## What Changes

- 新增 **agent trace 事件协议** `AgentTraceEvent`：定义 SSE / Celery 进度通道共同使用的事件 schema —— `step_start` / `step_delta` / `step_end` / `thinking_start` / `thinking_delta` / `thinking_end` / `system_notice` / `run_start` / `run_complete` / `cancelled` / `error`，每条事件携带稳定的 `step_id`（UUID）让前端做"流式增量更新"，避免重排 / 闪烁。
- **修改** `LogAnalysisAgent`（`app/agents/log_analysis/agent.py`）：在 `run()` 中注入一个 `trace_emitter: Callable[[AgentTraceEvent], Awaitable[None]] | None` 参数，把 `_handle_stream_message` 内部当前只写日志/append 到 `tool_trace` 的处理，重构为按事件分发到 `trace_emitter`（写日志保持，作为本地审计）。无 emitter 时行为与现状一致（向后兼容 Celery 旧调用方）。
- **修改** 主对话日志分析 (`app/services/log_analysis_chat_service.py`)：
  - 在创建 `AgentJob` 时构造一个 `trace_emitter`，把事件 `append` 到 `job.events`，SSE `_subscribe` 已有的 poll 机制就能自动把新事件推给前端；
  - 同时把所有事件持久化到 `AgentJob.trace_events: List[Dict]`，断线重连时**重放完整 trace**，让晚到的客户端能看到全部历史步骤（已落地的 reattach 机制只重放粗粒度 status，需要扩展）；
  - `done` 事件中新增 `trace_summary`：`{ thought_duration_seconds, tool_call_count }`，供前端直接渲染最终一行折叠汇总。
- **修改** 日志详情页分析 (`app/tasks/ai_analysis.py` + Celery 任务路径)：
  - Agent 在跑 Celery 任务时，把每条 `AgentTraceEvent` 通过 Celery `update_state(state='PROGRESS', meta={...})` 推到任务元数据，并**累积存到 Redis** 一个有界 list (`ai_analysis:trace:{task_id}`，TTL 1 小时，最多 N 条) 而不仅仅是 `update_state` 的"最后一条"覆写；
  - 新增 **SSE 端点** `GET /api/v1/logs/{log_id}/ai-analysis/trace/stream`：根据 `log_id` 查到 `ai_analysis_task_id`，从 Redis 拉取并增量推送 `AgentTraceEvent`；客户端断开再连可全量重放（与 chat 路径同样的语义）；
  - 任务完成后把完整 trace 持久化到 `LogRecord.ai_analysis_result.trace_events`（已有 `tool_trace` 字段升级为完整事件流），并写入 `trace_summary`。
- 新增 **前端组件** `AgentTraceStream.vue`（`frontend/src/components/`）：
  - 输入是 `AgentTraceEvent[]`（响应式数组）+ `running: boolean`；
  - 内部维护按 `step_id` 索引的步骤 map，按到达顺序渲染卡片；
  - 每张卡片支持四态：`running`（默认展开 + 流式 append 输出）/ `ok` / `error` / `cancelled`（默认折叠为一行，点击展开）；
  - thinking 卡片为单独样式（与 tool call 区别），运行中显示打字机光标；
  - 流末（收到 `run_complete`）自动把整组卡片折叠为一行汇总：`Thought for {duration}s · {tool_call_count} tool calls`，下方副标题固定文案 `Generated by AI and can make mistakes`，点击展开还原所有卡片；
  - 支持取消按钮（透传到上层组件，由上层调用现有 `/cancel` API）。
- **修改** `AIChat.vue`：把 `processChunk` 解析 SSE 时识别到的 `AgentTraceEvent`（与 `log_analysis_status` / `done` 并行下发）路由进新组件，挂在当前正在生成的 assistant 消息气泡里；
- **修改** `LogDetail.vue`：在 AI 分析模块挂载新组件，并接入 `/api/v1/logs/{log_id}/ai-analysis/trace/stream` SSE；任务完成后从 `ai_analysis_result.trace_events` 回放出同一组卡片（保证刷新页面后仍能看到完整 trace）。
- 新增 **取消按钮交互的统一文案与事件**：trace 流中渲染 cancel 触发与 cancel 完成两次事件（`system_notice` 即可），让用户清楚知道取消信号已收到。

### Out of Scope（明确不在本次范围内）

- 不改造非日志分析的对话流（`/ai-chat/chat/stream`、`chat_agent.py`），那条链路仍然只下发最终文本。
- 不改造 trace 的持久化存储格式以外的字段（如不引入新的 DB 表、不动 `LogRecord` 列结构，只扩展 `ai_analysis_result` JSON）。
- 不实现多用户共享同一条 trace 的协作视图。
- 不实现 trace 事件的细粒度权限控制（沿用现有 log / chat 的可见性规则）。

## Capabilities

### New Capabilities
- `agent-trace-stream`：定义 Claude Agent SDK loop 内部 assistant text / thinking / tool_use / tool_result / system / lifecycle 消息向前端实时透传的事件协议、传输通道（SSE for chat、SSE-over-Redis-replay for Celery）、断线重放语义、最终汇总 schema。
- `agent-trace-ui`：前端"类 Claude Code"步骤卡片组件 `AgentTraceStream.vue` 的渲染规范、卡片四态（running / ok / error / cancelled）与折叠行为、最终一行汇总 `Thought for Xs · N tool calls` 的呈现规则，以及在 AI 对话页和日志详情页两个场景的接入方式。

### Modified Capabilities
- `log-analysis-agent`：把现有"内部 `_handle_stream_message` 仅写日志和 tool_trace"行为升级为同时通过可选 `trace_emitter` 把每条事件向外推送；最终 `result` 字段中 `tool_trace` 扩展为完整事件流 `trace_events`（旧字段保留作为派生视图）并新增 `trace_summary`。

## Impact

- **后端代码**：
  - 新增 `app/agents/log_analysis/trace.py`（`AgentTraceEvent` 数据类 + JSON 序列化 + 事件类型枚举）。
  - `app/agents/log_analysis/agent.py`：`_handle_stream_message` 重构为发射 `AgentTraceEvent`，`LogAnalysisAgent.run` 接受 `trace_emitter`。
  - `app/services/log_analysis_chat_service.py`：`_run_job_async` 注入 emitter；`AgentJob` 增加 `trace_events` 字段；`_subscribe` 重放完整 trace。
  - `app/tasks/ai_analysis.py`：Celery 任务接入 emitter，把事件写入 Redis 有界 list；result 持久化新字段。
  - `app/api/logs.py`：新增 `GET /logs/{log_id}/ai-analysis/trace/stream` SSE 端点。
- **前端代码**：
  - 新增 `frontend/src/components/AgentTraceStream.vue`、`frontend/src/composables/useAgentTraceStream.ts`（SSE 解析 + 事件归并）。
  - `frontend/src/views/AIChat.vue`：在 `processChunk` 中识别并路由 `AgentTraceEvent`，挂载到当前 assistant 消息。
  - `frontend/src/views/LogDetail.vue`：在 AI 分析模块挂载组件并接入新的 SSE 端点。
- **API 契约**：
  - **新增** `GET /api/v1/logs/{log_id}/ai-analysis/trace/stream`（SSE，`text/event-stream`）。
  - `POST /api/v1/ai-chat/log-analysis/stream` 的 SSE 流中**新增**事件类型 `agent_trace`（payload 为 `AgentTraceEvent`），现有 `log_analysis_status` / `log_analysis_context` / `done` / `error` 全部保留并继续下发，老客户端忽略 `agent_trace` 即可不破坏。
  - `LogRecord.ai_analysis_result` JSON 中**扩展**字段 `trace_events`、`trace_summary`；旧字段 `tool_trace` 保留。
- **数据库**：无 schema 变更（事件流通过 JSON 字段承载）。
- **依赖**：无新增 Python / npm 依赖。已有 Redis 即可承载 trace replay 缓冲。
- **运维**：Redis 内存占用略升（按 1 小时 TTL × 任务并发数 × 每任务 < 256 KB 事件），需在容量评估中考虑。
- **向后兼容**：
  - 旧的前端（不识别 `agent_trace` 事件）仍可正常看到最终 `done` 文本结果；
  - 旧的 `LogRecord.ai_analysis_result.tool_trace` 字段仍由后端写入（从 `trace_events` 派生），供历史日志详情页不变量渲染。
