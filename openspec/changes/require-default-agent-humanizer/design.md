## Context

现有 Skills 由内置、Agent 上传及项目上传合并，再按问题相关性最多选取三个。物化只保证 SDK 可发现，实际加载仍由模型判断。

## Goals / Non-Goals

**Goals:** 两个默认 Agent 每轮完整加载 Humanizer-zh；新部署无需上传；保留事实和输出契约；可通过运行事件核实。

**Non-Goals:** 改变模型配置、扩展到其他 Agent 或引入额外模型润色请求。

## Decisions

1. 在共享源码目录保存上游原文、MIT 许可证、固定提交与 SHA-256。新增专用必需 Skill 注册表，仅关联 log_analysis / project_expert。
2. 必需 Skill 在普通合并后成为权威来源，始终物化且不参与相关性排名；每轮在可选 Skill 准备的异常捕获之外校验并读取完整文件。缺失则终止，不静默跳过。
3. 在两个 Agent 最终系统提示词中内联完整规则及技术适配约束，服务端加载不依赖模型是否调用 SDK Skill 工具。运行事件明确使用 server_prompt 加载方式，不伪造工具调用或声称模型已完成润色。
4. 适配约束优先于上游通用写作示例：保留证据、代码、数字、引用和不确定性；不虚构经历或感受；遵循 locale 和围栏 JSON，不额外输出评分表。
5. 必需风格 Skill 不启用现有纯文本 Skill 结果兜底。可选领域 Skill 仍按需加载，维持原有语义。

## Risks / Trade-offs

- [完整规则增加上下文] → 每轮仅注入一次，无二次模型调用，记录内容摘要便于审计。
- [模型不能提供绝对风格保证] → 保证规则加载和提示词执行要求，以真实问答验证输出；明确区分加载与模型行为。
- [生产存在任务/并发改动] → 先检查 Git、容器和活动任务，仅更新指定服务，保留卷与配置。

## Migration Plan

无需数据库迁移。提交源码与遮罩修复并推送子仓库/父仓库 gitlink；nr-test 检查后快进至确切提交，构建 backend/frontend，待任务空闲后重建 backend/worker/frontend。验收首问、追问与登录/注册弹窗。失败时可恢复原镜像，不修改数据卷。
